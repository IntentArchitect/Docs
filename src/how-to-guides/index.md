# How-to guides

Each guide here shows you how to do one thing in Intent Architect, in a short set of steps.

- [Build your own dashboards and dev tools with the agent](xref:how-to.build-your-own-dashboards) - see your pipelines, your pull requests or anything else you keep checking on one screen without leaving Intent Architect: have the agent build a small dashboard of your own and open it in the app preview, with live data every time you look.
- [Classify your codebase so reviews focus on what matters](xref:how-to.classify-your-codebase) - have the agent tag your code with what each part is for and how closely to review it, so you know which files in a large change to read first.
- [Connect an MCP server to your chat](xref:how-to.connect-an-mcp-server) - stop copying work items, tickets or messages into the chat: connect that system's MCP server, such as Azure DevOps, Jira or Slack, and the agent reads and updates it itself, in the same chat in which it works on your code.
- [Get it right the first time with Plan Mode](xref:how-to.get-it-right-with-plan-mode) - get the plan right before any code is written: check the data model, API and screens it sketches, comment on anything that's off and answer its questions, then choose the model that builds it and where.
- [Get visual reports on your system from the agent](xref:how-to.visual-reports) - ask the agent for a report on part of your system, such as who can call which endpoint, and get a document you can read at a glance: diagrams, tables and links to your model and code.
- [Open pull requests that prove they work](xref:how-to.prove-it-works) - have the agent show you its change works, with your tests, an AI review and your running app, then open a pull request that shows your reviewers what it checked.
- [Reuse your best prompts with Work Item templates](xref:how-to.work-item-templates) - write a prompt you keep retyping once, start a fresh chat from it whenever you need it, each in a worktree of its own, and turn it into a skill once your team wants it.
- [Review pull requests effectively](xref:how-to.review-pull-requests) - get through a big pull request, from a teammate or an agent, without missing what matters: let AI review it first, check the design on a diagram, spend your time on the code and tests that need a person, and hand your comments to an agent to fix.
- [Run agents in parallel](xref:how-to.run-agents-in-parallel) - keep several agents working while you carry on with your own work, each task in its own copy of your code so no agent touches your files or another agent's.
- [Set up tasks so the agent can build, test and run your app](xref:how-to.set-up-tasks) - give the agent your build, test and run commands so it can check its own work, try your app and get each new worktree ready, and run the same tasks yourself with one click.
- [Use Claude Code, Cursor or Copilot with Intent Architect](xref:how-to.use-claude-code-cursor-or-copilot) - keep the coding agent you already use: connect it from your terminal or editor so it models and generates your code there, or pick it as the AI in Intent Architect's chat to run tasks in their own worktrees and build from specs.
- [Use Spec Kit, Kiro, BMAD or OpenSpec with Intent Architect](xref:how-to.use-spec-kit-kiro-bmad-or-openspec) - keep the spec framework you already use: bring in the specs you have or run its own commands from Intent Architect, and see which code realizes each requirement.
- [Vibe coding, Plan Mode or Spec-Driven Development: when to use which](xref:how-to.vibe-coding-plan-mode-or-sdd) - get the outcome you're after: just prompt for a quick question or an easy fix, plan first for a larger goal, or use Spec-Driven Development when the requirements must be proven and stay true after the work ships.
- [Work across related codebases](xref:how-to.work-across-related-codebases) - give the AI agent code outside your solution, such as a frontend or a shared library, to read for context or change as part of the same task.
